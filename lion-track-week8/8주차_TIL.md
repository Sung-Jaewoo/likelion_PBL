# 📘 Today I Learned

### 1. 오늘 배운 내용
- 기존 JavaScript/JSX로 작성된 React 프로젝트를 TypeScript/TSX 프로젝트로 마이그레이션하는 방법
- `props`, `useState`, 이벤트 핸들러, API 응답 데이터에 타입을 지정하는 방법
- 공통 타입은 `src/types` 폴더에 분리하고, 유틸 함수는 `src/utils`, 커스텀 훅은 `src/hooks`에 분리하는 구조

### 2. 핵심 정리 (내 언어로)
- 컴포넌트 파일은 `.tsx`, 데이터나 유틸리티 파일은 `.ts` 확장자를 사용해야 한다는 것을 알게됨.
- `yarn build`를 실행하면 TypeScript 타입 검사와 프로덕션 빌드가 함께 진행된다는 것을 확인함.
- TypeScript: 코드가 실행되기 전에 데이터 구조와 함수 사용 방식이 맞는지 먼저 확인해 주는 도구!!
=> JavaScript에서는 그냥 넘길 수 있었던 값들도 TypeScript에서는 타입을 명확히 정해야 해서 처음에는 번거롭지만, 그만큼 실수를 미리 발견할 수 있다는 장점이 있음.
- 컴포넌트의 `props` 타입을 지정하니, 어떤 데이터가 컴포넌트에 들어와야 하는지 코드만 봐도 더 쉽게 이해 가능했음을 실감함.
결론: 단순히 파일 확장자만 `.tsx`, `.ts`로 바꾸는 것이 아니라, 데이터 구조와 함수의 흐름을 타입으로 정리하는 과정이 TypeScript 마이그레이션의 핵심!!

### 4. 느낀 점
- 처음에는 JavaScript를 TypeScript로 바꾸는 것이 단순히 확장자만 바꾸는 작업이라고 생각했는데, 실제로는 데이터와 컴포넌트의 관계를 더 명확하게 정리하는 작업이라는 것을 알게 되었다.
- 타입을 하나씩 붙이면서 내가 만든 데이터가 어떤 구조인지 더 잘 이해하게 되었고, 컴포넌트가 어떤 값을 필요로 하는지도 더 선명하게 보였다.
- 빌드 오류를 해결하면서 TypeScript와 빌드 도구가 프로젝트의 문제를 미리 알려주는 역할을 한다는 점이 인상 깊었다.
- 앞으로 React 프로젝트를 만들 때 처음부터 타입을 생각하면서 작성하면 유지보수하기 더 쉬운 코드를 만들 수 있을 것 같다.
